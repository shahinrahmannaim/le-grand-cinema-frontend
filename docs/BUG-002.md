# BUG-002 — Jour d’analyse décalé lors de la sérialisation

Le test HTTP de statistiques a détecté qu’un `date` PostgreSQL remonté comme `java.sql.Date` était sérialisé en instant UTC : le 7 novembre à minuit Paris apparaissait comme `2026-11-06T23:00:00.000Z`. L’interface pouvait alors afficher une date trompeuse dans les analyses.

La requête conserve le calcul du jour dans le fuseau `Europe/Paris`, puis convertit explicitement la date en texte ISO : `(starts_at AT TIME ZONE 'Europe/Paris')::date::text`. Le jour civil est ainsi distinct de l’instant de début de séance.

Non-régression : `SecurityHttpIT` exige un jour analysable par `LocalDate.parse`, tandis que les heures de séance doivent rester analysables par `Instant.parse`. `StatisticsIT` vérifie également le jour attendu et le classement week-end. Les tests de changement d’heure du catalogue restent conservés.
